# MCU 示例串口协议 v1

此协议用于软件验证，尚无配套真实固件。默认 dry_run 只发布 mcu/tx_frame，不打开串口。
传输当前支持 POSIX 串口 115200、8N1、无流控。

## 帧格式

所有多字节整数为小端：

| 字段 | 字节数 | 内容 |
|---|---|---|
| magic | 2 | ASCII MZ，即 0x4D 0x5A |
| version | 1 | 1 |
| type | 1 | 1=控制，2=状态 |
| payload_length | 2 | 载荷字节数，上限32 |
| sequence | 4 | 主机递增序号，uint32 回绕 |
| payload | 可变 | 如下 |
| crc | 2 | CRC-16/CCITT-FALSE，初值0xFFFF，多项式0x1021，不反射、无最终异或 |

CRC 覆盖帧头和载荷，不包含 CRC 本身。

控制载荷：left(uint16)、right(uint16)、ttl_ms(uint16)，共6字节。
左右拉绳 0..10000 对应 0..1；有效期1..500ms，**从 MCU 完整接收并校验成功时开始计时**。
主机转发时扣除已有数据年龄；串口传输本身会增加时延，实机需根据链路测量进一步收紧。
序号是通信桥独立递增的链路序号，不是 ROS ControlCommand.sequence。

状态载荷：flags(uint8)、actual_left(uint16)、actual_right(uint16)，共5字节。
flags=0 表示该示例认为执行器正常，其他值视为故障；左右反馈使用相同量纲。
状态帧 sequence 必须回显最近已接收的控制帧序号。主机只接受0.5秒内发出指令的回执，
相同序号的连续重复反馈不刷新链路活性。状态反馈不替代机器人定位。

## MCU 必须实现的行为

1. 处理分片、粘包、非法长度、CRC错误，不执行未完成校验的数据。
2. 对重复或过期控制序号拒绝重新执行/续期，正确处理 uint32 回绕。
3. 将归一化拉绳量通过实测标定转换为执行器目标，并限制范围和变化率。
4. 控制 TTL 到期、断链或本地故障时执行经过验证的翼伞回退策略。
5. 内环与看门狗独立于 ROS 主机，回报执行状态。

当前软件回退为左右零拉绳，即配平滑翔，不是停车、落地或完整的故障着陆策略。
实机协议未确定前，不应将该示例桥接到真实执行器。
